# Build plan

Work top to bottom, one task per session, with /next-task. Each task needs a test that fails before the change and passes after. Tasks marked [Josh] need Josh to act or approve; stop and tell him exactly what to do. Test fixtures are recorded responses from public data APIs (DNS, RDAP, crt.sh, NVD, and so on) or hand-written HTML. Never load a third party's web pages to make a fixture.

## Foundation
- [ ] F1. Skeleton. Create the reconbrief package (Python 3.11+), pyproject.toml with uv.lock, pytest, and a typer CLI named reconbrief. Add tests/ and tests/fixtures/recorded/. Create plugins/opportunity-recon/.claude-plugin/plugin.json. Create .claude-plugin/marketplace.json using the owner/name from `git remote get-url origin`. Done when: one smoke test passes, `reconbrief --help` runs, and `claude plugin validate` passes.

## Engine core
- [ ] F2. Data model. Pydantic models: Evidence, Asset, Finding (id, instance, title, attention talk/ask/background, confidence, observed, why_it_matters, what_the_engagement_does, assets, evidence ids, details), CheckStatus (found/absent/unknown plus reason), SourceStatus (with health), Bundle, and Snapshot. Done when: tests round-trip a bundle through JSON, and no model has a talk-track or question field.
- [ ] F3. HTTP client and address guard. A shared client with the User-Agent from SPEC, per-source rate limits, bounded retries, a response size cap, and a cache that lives with saved runs (A2). Add the global-address guard and manual redirects described in SPEC. Done when: hosts resolving to 127.0.0.1, 10.0.0.5, and 169.254.169.254 cause zero connections, a redirect to http://127.0.0.1/ is refused, and a public address passes.
- [ ] F4. DNS resolver. Async resolution that returns CheckStatus-aware results, with TCP retry on timeout or truncation. Done when: a resolver that raises LifetimeTimeout yields unknown, and a recorded 40-record TXT answer parses.
- [ ] F5. Pipeline. Stages (discover, resolve, enrich, web, crawl, vuln, company); sources within a stage run concurrently; each source gets a time budget, and source health is recorded. Contact levels none, dns, web, and crawl, with web as the default. Done when: tests show stage order, concurrency, a failing source marked failed without stopping the run, and contact-level gating.
- [ ] F6. Build and install scripts. scripts/build_wheel.py builds the wheel into plugins/opportunity-recon/vendor/. scripts/install_engine.py installs that wheel by exact path with --no-deps, then installs pinned, hashed dependencies (offline from vendor/ when the wheels exist there, using the platform from A1). Done when: install works in a clean venv; one test fails when the vendored wheel differs from reconbrief/; and another test fails if any file in plugins/ or docs/ installs reconbrief by name. [Josh: register the reconbrief name on PyPI so nobody else can publish under it.]

## Sources
- [ ] S1. DNS records. For each seed: A, AAAA, NS, MX, CAA, SOA, TXT, SPF, DMARC, a fixed list of DKIM selectors, MTA-STS, TLS-RPT, and the Microsoft 365 service names; wildcard detection. For each discovered host: addresses, CNAME chain, and dangling CNAME detection. Done when: recorded fixtures cover a normal domain, a wildcard domain, a dangling CNAME, and a timeout.
- [ ] S2. Certificate Transparency. crt.sh with backoff on 502 and 503, plus a second CT source whose terms allow commercial use (document which one and why). Done when: a mocked crt.sh 502 falls back to the second source, and both failing marks health failed.
- [ ] S3. RDAP. Registrar, dates, nameservers, DNSSEC, normalized statuses, and registrant org (marked redacted when it is). Done when: a recorded Verisign response for a locked .com yields transfer_lock true.
- [ ] S4. Historical hostnames. Wayback CDX and urlscan.io search. Done when: recorded fixtures parse and out-of-scope names are dropped.
- [ ] S5. Network context. RIPEstat holder and country per IP, published cloud and CDN ranges, and Microsoft 365 tenant detection. Done when: recorded fixtures parse, and an IP in a published AWS range is labeled AWS.
- [ ] S6. Page loader. robots.txt check, then one root page load per live host through the F3 guard, up to max_hosts. Prioritization order: seeds, www, non-wildcard hosts, wildcard hosts. Collect certificate details via binary_form, error classification, headers, cookies, title, technologies, and banners with distro tags kept. Done when: a local TLS test server with an expired certificate (generated with cryptography, a dev dependency) records the expiry, and a wildcard host whose page matches the wildcard response is marked as not distinct.
- [ ] S7. Trust and security posture. Use the discovery rules from SPEC. Collect stated certifications, the last stated pentest year, bug bounty or disclosure program, and trust-center vendor, all with word-boundary patterns. Done when: "Get the Acme advantage" yields no vendor, and a soft 404 yields no trust center.
- [ ] S8. Company profile. Wikidata, GLEIF, and SEC EDGAR, using trusted names and second-signal corroboration as in SPEC, plus ownership type. Done when: an uncorroborated GLEIF hit never sets legal_name, and a guessed name never triggers a match.
- [ ] S9. Vulnerability context. The CISA KEV catalog, and NVD lookups for banner versions, paged in full and keyed by CPE. Done when: a recorded multi-page NVD response produces full counts.
- [ ] S10. Opt-in crawl. Read-only, links only, robots.txt per origin with * and $ support, page and depth caps, rate limits. It maps forms, login pages, and API endpoints referenced in page code, and collects published emails on in-scope domains. Done when: a crawl that follows a link from www to app requests app's robots.txt first and skips a disallowed path.

## Finding rules
- [ ] R1. Email and domain rules: email spoofing (from SPF and DMARC CheckStatus, nothing when unknown) and domain registration (expiry, transfer lock, DNSSEC). Done when: unknown SPF yields no finding, and the locked .com fixture yields no lock problem.
- [ ] R2. Hostname rules: dangling DNS (with service-specific takeover fingerprints), non-production hosts (strong and weak words), internal names in certificates, stale hostnames, and internal addresses in public DNS. Done when: wildcard-only names produce no non-production finding, a "demo" host with no page signal produces none, and a host on 10.0.0.5 yields only the internal-address finding.
- [ ] R3. Web rules: certificate issues, login portals, plain HTTP, security headers, version disclosure, known vulnerable software, API docs, and default pages or directory listings. Done when: a marketing page naming GitLab, Confluence, ADFS, and cPanel yields no portal finding; real login page fixtures do; a Red Hat banner yields at most background; and the Microsoft 365 autodiscover fixture yields no portal or certificate finding.
- [ ] R4. Context rules: tech stack, attack surface, trust and compliance (absence only when checked), likely compliance drivers, and AI exposure (strong evidence only). Done when: a DNS-level run yields no trust absence finding, and a page that only mentions OpenAI in its text yields no AI finding.

## Engine outputs
- [ ] O1. Run outputs and CLI. `reconbrief run <domain>` writes bundle.json, snapshot.json, and evidence.csv to the run directory (A2), with scoping counts that say "not checked" for skipped sources. `reconbrief preflight` follows SPEC. Done when: schema tests pass for all three files, and preflight fails for one blocked host and for a mocked proxy 403.
- [ ] O2. Offering recommendation. Given the user's offering list and a bundle, return one lens with the finding instances behind it, choosing only from that list. Done when: a profile listing only external-pentest always gets external-pentest.
- [ ] O3. Deck renderer. `reconbrief deck --outline <json>` validates the outline (every slide cites findings or named sources) and renders the .pptx with python-pptx, on a brand template when one is given. Footers show source names and the run date, never finding IDs. Done when: a rendered test deck contains no finding IDs and uses the template's layouts.
- [ ] O4. Evaluation harness. `reconbrief eval run` writes a review CSV with one row per finding and an empty verdict column (correct, wrong, embarrassing). `reconbrief eval summarize` prints a false-positive rate for each rule. Done when: a synthetic sheet summarizes correctly.
